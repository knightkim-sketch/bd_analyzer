## 1. 왜 만드는가

odyssey (자사 HW AV1 인코더) 는 warped motion / global motion 이 전부 꺼져 있습니다.
선행 조사에서 남은 개선 후보 중 근거가 가장 강한 항목으로 나왔습니다.

| 항목 | 실측 이득 | 근거 |
|---|---|---|
| warped motion | **+4.168% mean** (Sports-1bf7 +6.748%) | high-motion 3클립 aomenc ablation. SVT p2 가 24.9% 사용 |
| **global motion** | **+1.226% mean** | 같은 실험. warped 의 약 30% 를 **프레임당 모델 1개**로 가져감 |

global motion 이 선택된 이유는 **per-block warp 보간기가 필요 없어 HW 비용이 자릿수로 싸기 때문**입니다.

bd_analyzer 에서 **추정기 품질을 먼저 검증**하고, 품질이 확인되면 odyssey 가 CSV 를 읽어
open-loop ME 후보로 주입해 BD-rate 를 잽니다. **비트스트림·디코더에는 영향이 없습니다**
(AV1 `global_motion_params` 는 이번 범위 밖).

## 2. 확정 파라미터 (Knight 결정, 변경 시 확인 필요)

| 항목 | 값 |
|---|---|
| 산출물 | ME 후보 MV 전용 |
| 윈도 | 프레임 **4×4 그리드 = 16개**, 겹침 없음 |
| 다운샘플 | **width 기준** `1/2ⁿ`, `width>>n ≤ 512` 인 최소 n. 세로도 같은 n |
| 집계 | 윈도별 MV 그대로 (**전역 모델 피팅 없음**) |
| 스무딩 | 5-tap binomial `[1,4,6,4,1]/16` |
| 밝기 보정 | **DC + gain 둘 다 기본 적용** |
| 탐색 범위 | **원본 기준 고정** `R_orig` 기본 ±128 px |
| 참조 | **가장 가까운 과거 참조 1개** |
| 윈도→블록 | 최근접 윈도 (nearest, 계단함수) — 소비 측(odyssey)에서 적용 |

```
3840 → n=3 → 480×270, 윈도 120×67, R_ds 16
1920 → n=2 → 480×270, 윈도 120×67, R_ds 32
1280 → n=2 → 320×180, 윈도  80×45, R_ds 22 (상한)
 512 → n=0 → 512×288, 윈도 128×72, R_ds 36 (상한)
```

`R_ds = clamp(R_orig >> n, 4, min(w,h)/2)`.
**상한이 없으면 288p 에서 ref 윈도 겹침이 0 이 됩니다.**

## 3. 알고리즘

### 3.1 다운샘플

`MePlane::downscaleOdysseyMeanpool(1 << n, pad)` 를 씁니다.
odyssey 의 기본 다운스케일러가 `MEANPOOL_2D` 이므로 **반드시 meanpool 쪽**을 써야
나중에 인코더로 옮길 때 결과가 어긋나지 않습니다 (`MePlane.h:5-22` 가 설명하듯
두 커널은 step 2 에서는 같고 step 4 부터 갈라집니다).
박스 평균 자체가 저역통과라 **별도 안티에일리어싱은 넣지 마십시오.** 8bit 유지.

### 3.2 윈도 분할

```
x0 = Wd*i/4,  x1 = Wd*(i+1)/4      i = 0..3
y0 = Hd*j/4,  y1 = Hd*(j+1)/4      j = 0..3
```

정수 나눗셈이 나머지를 분산시켜 윈도 간 크기 차가 최대 1 px 입니다.

### 3.3 적분 투영 — 누적합 평면 2장이면 끝납니다

**이 설계의 핵심입니다.** 윈도마다 따로 합을 돌 필요가 없습니다.

```
SX[y][x] = Σ_{u<x} px(u,y)        행 누적합
SY[y][x] = Σ_{v<y} px(x,v)        열 누적합

Pv[y] = SX[y][x1] - SX[y][x0]     y ∈ [y0,y1)    → y 축 탐색용
Ph[x] = SY[y1][x] - SY[y0][x]     x ∈ [x0,x1)    → x 축 탐색용
```

y 축 탐색은 ref 윈도를 `[x0,x1) × [y0+d, y1+d)` 로 옮기는 것이고, 그 Pv 는
`SX[y+d][x1] - SX[y+d][x0]` 입니다 — **x 범위가 그대로**라 같은 `SX` 를 재사용합니다.
x 축도 대칭입니다.

→ **평면 2장이 두 축 · 모든 d · 모든 윈도를 전부 커버합니다.**

ref 는 `[y0-R, y1+R)` / `[x0-R, x1+R)` 확장 구간이 필요하고, 프레임 밖은
`MePlane` 의 replicate border 가 처리합니다 (`MePlane.h:66` 의 유효 좌표 범위 참고).

- 메모리 `2·Wd·Hd·4B` — 1/8 4K 에서 1.04 MB
- 연산 `2·Wd·Hd` add — 1/8 4K 에서 259k

> 이 구조가 odyssey 의 기존 PMD 구현이 가졌던 "참조마다 current 투영을 재계산" 비효율을
> 구조적으로 없앱니다. org 쪽 평면은 참조와 무관하게 프레임당 1회입니다.

### 3.4 스무딩

org·ref 의 모든 1D 투영에 적용. 가장자리는 복제.

```
s[i] = (p[i-2] + 4*p[i-1] + 6*p[i] + 4*p[i+1] + p[i+2] + 8) >> 4
```

전부 shift-add 입니다. `p` 는 최대 120 px × 255 ≈ 30,600 이라 16배 가중해도 32bit 여유가 있습니다.
대칭 커널이므로 **피크 위치가 이동하지 않습니다**.

### 3.5 DC + gain 보정

윈도별·축별로 **d=0 정렬 상태**에서 `org ≈ a·ref + b` 를 1차 회귀로 구합니다.

```
mo = Σo/L,  mr = Σr/L
a  = Σ(o-mo)(r-mr) / Σ(r-mr)²
a_q = clamp(round(a * 4096), 2048, 8192)       Q12, 0.5 ~ 2.0
Σ(r-mr)² 이 임계 이하(평탄한 윈도) → a_q = 4096
```

**DC 는 d 마다 다시** 구합니다. ref 투영의 누적합을 미리 만들면 O(1) 입니다.

```
Rsum[k] = Σ_{t<k} r[t]
mr(d)   = (Rsum[d+L] - Rsum[d]) / L
```

최종 매칭 비용:

```
cost(d) = Σ | (o[i] - mo) - ((a_q * (r[i+d] - mr(d))) >> 12) |
```

`a` 는 d=0 에서 **한 번만** 구해 전 d 에 재사용합니다. d 마다 다시 구하면 상관 계산이
한 패스 더 붙습니다 (정규화 상호상관이 되지만 이번 범위에서는 과합니다).
평균 제거가 들어가 있어 **페이드·조명 변화·노출 변화에 강해집니다.**

### 3.6 1D 탐색 — 두 축 완전 독립

```
for d = -R_ds .. +R_ds:  cost(d)
d* = argmin;  cost(d*) 와 cost(0) 을 함께 기록
```

stride 1 전탐색, 서브픽셀 없음.

> **두 축의 결과를 하나의 (dx,dy) 로 합치지 마십시오.** odyssey PMD 소스 주석에 남은 교훈입니다 —
> *"확신 있는 한 축을 확신 없는 다른 축과 묶으면 좋은 쪽까지 같이 죽는다."*
> 축별 accept 플래그를 **따로** 내고, 조합은 소비 측(odyssey)에서 합니다.

> **축 선택 휴리스틱을 넣지 마십시오.** "이번엔 세로만 보자" 같은 최적화는 odyssey 에서
> 이미 실패했습니다 — 이전 프레임 MV 로 축을 고르려 했으나 Sports 90.5% / ElFuente 100% 의
> SB 에서 `|mv.y| − |mv.x|` 가 full-pel 0 이라 판별 불가였습니다.
> libaom(`mcomp.c:2059`) 과 SVT(`motion_estimation.c:1611-1637`) 모두 **두 축을 항상 탐색**합니다.

### 3.7 채택 게이트 — 2단, G2 가 핵심

```
g1 = (cost(d*) * 16 < cost(0) * 15) && (d* != 0)      /* 투영 비용비, 6.25% 개선 요구 */
g2 = (sad2d(dx*, dy*) * 2 < sad2d(0, 0))              /* 실제 2-D SAD, 2배 마진 */
accept = g1 && g2
```

G2 는 다운샘플 영상에서 `blockSad()` (`MeCost.h:32`) 를 **두 번** 부르면 됩니다.
축이 아니라 **(dx,dy) 쌍**에 대해 판정하고, 한 축만 g1 을 통과한 경우 다른 축은 0 으로 둡니다.

> **G2 를 빼지 마십시오.** odyssey 선행 작업(PMD)의 최종 결론이 정확히 이것입니다.
> 투영 비용비만 게이트로 쓴 PMD 가 로컬에서는 −6.051% 를 냈는데 AWCY 에서 회귀했습니다
> (S1 ElFuente +0.080, S2 Sports +0.076, worst 클립 +1.457).
> 사후분석 결론은 "투영 비용이 아니라 **실제 블록 SAD, 2배 마진**" 이었고,
> libaom 의 같은 게이트가 `var_based_part.c:1366` 의 `*y_sad < (y_sad_zero >> 1)` 입니다.

### 3.8 스케일 환산

```
mv_fullpel    = d* << n
mv_quarterpel = d* << (n + 2)        ← 출력 단위
```

odyssey ME 후보 리스트가 quarter-pel 단위이고 ME 코어가 공통 `>> 3` 을 걸어
half-res full-pel 로 착지시킵니다. PMD 가 full-res(n=0)에서 `d << 2` 로 주입한 것과 같은 규약입니다.

### 부호 규약 — 실측으로 확정했습니다

MV 는 **current 에서 reference 를 가리킵니다**: `pred(x) = ref(x + mv)`.
따라서 **화면 내용이 오른쪽으로 d px 움직였으면 dx = −d** 입니다.

odyssey 에서 end-to-end 로 확인했습니다 (프레임마다 +24 px 씩 오른쪽으로 평행이동시킨
합성 클립, low-delay, CRF 39, 16프레임):

| 공급한 dx | 결과 |
| --- | --- |
| GM 끔 | 5,843 byte |
| **dx = −96 qpel (= −24 px, 올바른 부호)** | **5,280 byte (−9.6%)** |
| dx = +96 qpel (부호 반대) | 5,840 byte (사실상 변화 없음) |

**부호를 뒤집으면 이득이 0 이 되고 오류처럼 보이지 않습니다.** V1 합성 테스트에서 반드시
부호까지 검증하십시오.

**양자화 주의**: 1/8 이면 MV 격자가 8 px 입니다. ME 중심값 용도이므로 후속 refine
(odyssey `ODY_ME_FULL_MAX_SR_W = 16`)이 덮지만, **격자가 refine 범위를 넘으면 안 됩니다.**
1/8(8px)·1/4(4px) 모두 범위 안입니다.

## 4. 출력 계약 — odyssey 와의 인터페이스

CSV 한 줄 = 윈도 하나. 프레임당 16행 (참조 1개).

```csv
poc,ref_poc,win_i,win_j,n,dx_qpel,dy_qpel,accept_x,accept_y,
cost_best_x,cost_zero_x,cost_best_y,cost_zero_y,a_q_x,a_q_y,sad2d_best,sad2d_zero
```

- **`poc` / `ref_poc` 는 표시순서(display order) 인덱스여야 합니다.** odyssey 의 `order_hint` 와
  맞춥니다. 디코드 순서로 쓰면 소비 측에서 프레임이 어긋나고, 증상이 "왜인지 이득이 없다" 로만
  나타나 디버깅이 매우 어렵습니다
- `dx_qpel`/`dy_qpel` = `d* << (n+2)`. accept=false 인 축도 값은 쓰되 플래그로 구분
- 비용·`a_q` 원값을 남겨야 **게이트 임계를 나중에 데이터로 고를 수 있습니다**

JSON 도 함께 내면 분석이 편합니다.

### 참조 1개 선택이 커버리지에 주는 영향 — 측정값

odyssey 는 superblock 마다 **여러 (current, reference) 쌍**으로 ME 후보를 만듭니다.
리스트 2개 × 참조 여러 개에 더해 MCTF 경로까지 같은 후보 빌더를 지나갑니다.
CSV 가 참조 하나만 담으면 나머지 질의는 전부 빈손으로 돌아갑니다.

odyssey 에서 측정한 조회 적중률 (`[GM] lookups ...` 로그):

| GOP | 적중률 |
| --- | --- |
| `--max-gf-interval 16` (계층 GOP, 출하 설정) | **24.4%** |
| `--max-gf-interval 1` (low-delay) | **51.7%** |

즉 **출하 설정에서는 질의의 약 3/4 가 GM 후보를 못 받습니다.**
이것이 이득을 깎는지는 V6 에서 드러납니다. 깎는다면 선택지는
(a) `order_hint` 비율로 다른 참조에 선형 외삽, (b) 참조를 더 추정 — 두 가지입니다.
지금은 비용을 아끼는 쪽으로 결정된 상태이고, 이 수치가 그 결정의 대가입니다.

## 5.5 odyssey 쪽 소비 경로는 이미 구현·검증되어 있습니다

CSV 를 받아 ME 후보로 넣는 쪽은 `odyssey-encoder-algoritm` 에 들어갔습니다
(`--gm-mv-file`, `analyzer/source/gm_mv.c`, 후보 슬롯 `CAND_GM`).
합성 CSV 로 다음을 확인했습니다:

- CSV 가 없으면 **기존 동작과 bit-exact**
- 후보가 방출된 횟수와 목록 내 위치, 조회 적중률이 `[GM]` 로그로 찍힘
- 순수 평행이동 클립에서 **올바른 MV 를 주면 −9.6%**, 틀린 부호를 주면 변화 없음

따라서 Part A 가 CSV 를 내놓는 즉시 BD-rate 측정이 가능합니다.
**CSV 포맷(§4)과 부호 규약(§3.8)만 맞추면 됩니다.**

## 8. 알려진 리스크

1. **다운샘플 해상도로 내리는 것 자체가 최대 리스크입니다.**
   odyssey PMD 를 half-res(1/2)로 내렸을 때 52bb 가 **+3.5%** 로 무너졌고, 당시 결론이
   "full resolution 필수" 였습니다. 다만 PMD 는 SB(64×64) 안을 16px 4그룹으로 쪼개
   **적분 길이가 64** 였고, 이번은 윈도가 프레임의 1/16 이라 **적분 길이가 120** 입니다.
   구조가 달라 같은 결과가 날 이유는 없지만 **V4 로 반드시 실측해야 합니다.**
2. **윈도 16개는 공간 해상도가 매우 낮습니다.** 사람이 움직이는 국소 모션은 못 잡습니다.
   이건 전역/카메라 모션 전용 도구이고, 그래서 윈도별 게이트가 반드시 필요합니다
3. **조리개 문제(aperture problem)** — 가로 구조만 있는 윈도는 세로 변위를 못 정합니다.
   축을 독립으로 돌리므로 축별 게이트가 자연히 처리합니다
4. **1D 투영의 다중 최소점** — 울타리·텍스트 같은 주기 패턴에서 최소점이 여럿입니다.
   스무딩이 완화하지만, 2순위 최소값 대비 비율 체크를 추가할지는 V4 후 판단합니다
5. **줌/회전** — 투영 매칭은 윈도 내부가 순수 평행이동이라고 가정합니다.
   줌은 프로파일을 **이동이 아니라 신축**시켜 매칭 품질이 떨어집니다.
   16윈도의 d 가 체계적으로 다르게 나오는 것으로 줌을 감지할 수는 있습니다

### 구현 중 바뀐 것 — 전부 합성 실측 근거, Knight 승인

1. **gain 은 d=0 이 아니라 찾은 d* 에서 적합합니다 (§3.5 변경).**
   움직임이 있으면 d=0 의 두 프로파일은 정렬되지 않아 기울기가 0 근처로 나오고 하한 0.5 에 걸립니다.
   그 gain 이 정답 d 의 비용까지 망칩니다 (정답 d 에서도 비용이 `|1−a|·Σ|o−mo|` 로 남음).
   1패스 구조에서 1/f 288p 단일축 8px: **보정 off·DC 16/16, d=0 gain 5~10/16.** 현 구조에서 gain
   적합 위치만 되돌린 A/B (Algory): (0,−16) 15 → 6, (+24,−16) y 15 → 5. 하한 0.5 고착은 짧은 세로
   축(L=72)에서 7/16 윈도, 가로 8px 에서는 0.65~1.09 로 양쪽으로 흩어지는 쪽이 원인이었습니다.
2. **교차 보정 패스 (§3.6 보강).** 한 윈도의 세로 프로파일은 그 윈도의 열을 더한 것이라, 가로로도
   움직였으면 열 일부가 ref 에서 다른 열이 되어 잡음이 됩니다. 패스 구성:
   1차(각 축 자기 구간, DC) → 2차(다른 축의 1차 d 만큼 ref 의 적분 구간을 옮겨 재탐색, DC) →
   3차(DC+gain 이면 2차 d* 에서 gain 적합 후 재탐색). **축은 여전히 따로 탐색·게이트**하고 하나의
   결정으로 묶지 않습니다. 1/f 288p (+24,−16) 에서 정답 윈도 1~6/16 → 13~15/16.
3. **축별 G2 (§3.7 보강).** 쌍 G2 에 더해 축마다 `sad2d(dx,dy)·2 < sad2d(그 축을 0 으로)` 를 요구합니다.
   쌍 G2 만으로는 확신 있는 축이 다른 축의 잡음 값을 데리고 통과했습니다 — 1패스 구조에서 1/f 288p
   세로만 이동 시 가로 오채택 9/16 → 0, 현 구조에서 (+24,0) 이동의 세로 오채택 4 → 0 (Algory).
   위험: 한 축의 실제 이동이 작고 내용이 매끄러우면 그 축을 빼도 SAD 가 2배가 안 돼 **맞는 축을
   기각**할 수 있습니다 — 미측정.

### 알려진 결함 — 2026-10-06 해결 (Knight 결정: step 2 를 n 번 반복)

GM 의 다운샘플은 이제 `downscaleOdysseyMeanpool(2)` 를 n 번 연쇄합니다. step 2 는 odyssey 커널이
정확한 평균을 내는 구간이라 인코더의 같은 블록을 그대로 쓰면서 값은 실제 평균(단계별 반올림)이 됩니다.
`MePlane` 함수 자체는 인코더 일치를 위해 그대로 둡니다. 합성 8K (n=4, +32/−16) 16/16 정확.
비용: SJTU Marathon 4K 프레임당 20.8 → **30.7 ms** (중간 단계 평면). 1080p(n=2) 는 단일 step 4 대신
step 2 두 번이라 반올림 차이만큼 값이 달라질 수 있습니다.

아래는 해결 전 기록입니다.

**meanpool step ≥ 8 이 밝기를 줄였습니다** (Algory 실측). `MePlane::downscaleOdysseyMeanpool` 의
반올림 `(sum + (1<<(step-1))) >> step` 은 step 2·4 에서만 평균이고, step 8 은 64샘플을 256 으로
나눕니다. 평탄 200 → step 2: 200, 4: 200, **8: 50, 16: 1.** odyssey 커널을 그대로 옮긴 것이라
(§3.1 "반드시 meanpool") 블록 ME 는 step 2 만 써서 문제가 없었지만, GM 은 4K(n=3) 에서 step 8,
8K(n=4) 에서 step 16 을 씁니다. 4K 는 1/4 밝기·2bit 손실, **8K 는 사실상 동작 불가**.
합성 4K V1 은 통과하므로 테스트가 잡지 못합니다.

## 12. 원본 해상도 정제와 GM 창 (2026-10-06, Knight 결정)

### 정제 — 1/2ⁿ 에서 256 탐색 후 원본에서 ±16

- `GmParams::rOrig` 기본 **256**, `refineRange` 기본 **16**. 상한(가장 작은 윈도의 절반)은 유지했으므로
  실제로 넓어지는 것은 4K 뿐입니다 (R_ds 16 → 32). 1080p 는 33, 288p 는 36 에서 잘립니다.
- 거친 결과 `d<<n` 을 중심으로 **원본 해상도 1D 투영**을 ±16 재탐색합니다. 같은 3패스(교차 구간 이동 →
  DC → d* 에서 gain)이고, 프로파일은 누적합 평면 없이 직접 합산합니다(원본 4K 누적합 평면은 132 MB×2).
  gain 의 `num·4096` 은 원본에서 64비트를 넘어 128비트로 계산합니다.
- **게이트는 다운샘플 해상도에서 판정한 그대로** 두고 정제는 값만 바꿉니다. 정제를 끄면 출력이
  `d<<n` 과 정확히 같고, 켜도 모든 윈도의 거친 d·게이트가 같음을 단위 테스트로 고정했습니다.
- n = 0 (≤ 512 폭) 은 더 고운 해상도가 없어 정제하지 않습니다.
- CSV 끝에 `dx_coarse,dy_coarse` (거친 값, 원본 px) 를 덧붙였습니다. 앞 19열은 `--r 128 --refine 0` 에서
  이전 출력과 바이트 동일합니다.

| 실측 | 정제 끔 | 정제 켬 |
|---|---|---|
| SJTU Marathon 4K raw, 프레임당 | 6.8 ms | **20.8 ms** |
| Sports_1080P-1bf7 (1080×1080), 프레임당 | 2.2 ms | 5.0 ms |
| 4K 10프레임, 정제가 값을 옮긴 폭 | — | 최대 7 px (160윈도 중 151 은 0) |

합성 V1 효과:
- 4K (n=3) 두 텍스처 (+24,−16): **16/16 정확 (full-pel)**.
- 1080p 중간 이동: 정확. 큰 이동 (±64, ±120) 에서 **들어오는 쪽 가장자리 윈도가 1~2 px** 어긋납니다 —
  원본 해상도에서는 ref 구간이 복제 경계를 더 많이 읽어 프로파일이 치우칩니다. 거친 단계에서 정확했던
  가장자리 윈도가 정제 후 1 px 틀어지는 경우도 있습니다(합성 패닝 클립 i=3 윈도 dy 4 → 5).
  후보 해법은 **ref 가 실제로 존재하는 영역으로 합산 구간을 자르는 것** — 설계(복제 경계) 변경이라 보류.
- 엄격 판정은 n > 0 에서 **정확 일치**로 강화했습니다(정제 후엔 2ⁿ 양자화가 없음). 그래서 FAIL 수는
  42 → 51 로 늘었지만, 늘어난 것은 위 1~2 px 가장자리 건입니다.
